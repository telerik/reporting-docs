## Method, Scoring, and Severity

The accessibility-doc-optimization skill supplies eight dimensions. User overrides govern: source only; absent local content scores 5; KB titles come from metadata, so no H1 is required and an initial H2 is valid; KB table-header issues are ignored, but empty data cells, unsuitable structure candidates, and other table checks are not exempt. Unresolved snippet/include contents are neither evaluated nor presumed accessible.

### Exact Integer Score Mapping

Apply independently to each dimension, in the following first-match order. Findings are counted individually, not by article:

| Condition | Score |
| --- | ---: |
| At least one Critical finding | 1 |
| At least two High findings | 1 |
| Exactly one High finding | 2 |
| No Critical/High and at least six Medium findings | 1 |
| No Critical/High and three to five Medium findings | 2 |
| No Critical/High and one to two Medium findings | 3 |
| No Critical/High/Medium and at least three Low findings | 3 |
| No Critical/High/Medium and one to two Low findings | 4 |
| No confirmed source findings, or absent applicable local content | 5 |

Count-based severity mapping interpolates the skill’s 1/3/5 anchors and explicitly defines 2/4. It is an auditable baseline convention, not a WCAG failure scale. A dimension score of 1 does not itself create a Critical finding. Each article’s `weighted_score_unrounded = sum(integer_score × integer_percent_weight) / 100`; `overall_score` rounds that value to one decimal using decimal ROUND_HALF_UP. The repository mean is the sum of those integer numerators divided by `100 × scored_articles`, not the mean of rounded `overall_score` values. Dimension means use unrounded integer scores. Absent checks remain 5 rather than omitted denominators.

### Detection and Judgment Boundaries

- Frontmatter is parsed with PyYAML 6.0.1 after UTF-8 BOM removal and whitespace normalization of delimiter lines, while preserving original line numbering. The leading-space KB delimiter described above is explicitly accepted as metadata for this source assessment; this does not assert how every publishing engine would handle it. Markdown-it-py 3.0.0 CommonMark tokens plus its table rule isolate ATX/setext headings, reference/inline links and images, fenced/indented code nested in lists or blockquotes, inline code, Markdown tables, and HTML tokens. Standard-library HTMLParser tracks actual HTML anchors, images, headings, tables/cells, `pre`/`code`, and excludes script/style/code from prose. Recognized >caption directives are also inspected outside code: when an immediately following pipe block parses independently as a table, its intended structure is assessed with original line offsets even if plain CommonMark swallows it into lazy blockquote prose. This is not the site renderer; parser differences remain a limitation.
- Critical requires source-evidenced loss of clearly informative/essential content, not a short article lacking H1. Missing/generic image alternatives with uncertain purpose become Human Review Required without severity. No such clearly informative missing-alt case was found in the current snapshot; this does not certify existing alternatives. PR2303’s historical patches were not used as evidence.
- High: additional H1s; two or more genuine hierarchy skips in one article; non-KB data tables with absent/empty semantic headers; at least two unlabelled fenced blocks in one article; and individually source-reviewed misnested list fences that absorb instructions or fragment examples. Single hierarchy skips, missing standard-article H1, empty leaf sections, empty data cells, one unlabelled fence, and clearly generic informative alternatives are Medium. Indented HTTP request/response literals are not promoted to High merely because indentation syntax has no language tag.
- Medium/Low are conservative maintainability/readability signals, not measured assistive-technology failures. Medium link labels use an exact case-insensitive set: here, click here, this article, this page, read more, more, link, this link, learn more, see here, these articles. Bare prose URLs/URL labels are Low; intentional code URLs are excluded. Link-label/destination conflicts remain contextual human review, not automatic violations.
- Plain-language candidates: >40 natural-language words in a parser-isolated prose sentence, split on sentence-ending punctuation followed by an uppercase letter (Medium); utilize/utilizes/utilizing/aforementioned/heretofore/henceforth (Low). Inline code, URLs, paths/qualified identifiers, camelCase, and snippet syntax are excluded. No Flesch-Kincaid grade, passive-voice rate, acronym-definition completeness, or global jargon score is claimed; technical prose and sentence boundaries need review.
- Tables: empty non-KB header labels/no HTML `th` are High only where reviewed rows express genuine data relationships. Blank body cells are Medium by row, with precise column numbers; inline code, image alternatives, inline SVG geometry, and actual HTML cell text count as data, not blanks. SVG purpose/naming and irregular HTML row structure are recorded separately for human review, never as fake empty-cell findings. A ≥5-column table lacking a prose lead-in in the preceding three source lines is Low. Blank cells may intentionally indicate unused independent categories; that interpretation is called out for human review, not asserted as missing facts. KB header exemption does not exempt other issues. Complex spans and table suitability require human review; the image/caption layout table in report-items/graph/overview.md:23 was source-reviewed and recorded as Medium, rather than misclassified as missing data headers.
- Formatting: real nonlink `u` markup is a Low style-independence signal. Color/bold/italic references with visual-instruction wording are review candidates only; presence of a style word is not proof of visual-only dependence. Callout checks compare actual prose labels with `_plugins/alert_generator.rb:7–16`, including its exact no-space markers; marker mismatch or an untyped prose/list callout label is Low, empty messages Medium. A heading beginning Important is not automatically an admonition. Callout severity, appropriateness, and overuse are not inferred exhaustively.
- Code: no-language fenced blocks are reported at each opening fence; text/error/output samples can use text. Intro checks accept neighboring prose, headings, or list labels within four source lines; missing context is Low. Consecutive blocks separated only by whitespace share the first block’s introduction; fence-only boundaries do not produce repeated missing-introduction findings. Indented literals are Low suggestions to use tagged fences, except obvious Expression/Operator/Value prose accidentally parsed as code (Medium). Unannotated HTML `pre`/`code` is Medium. Placeholder consistency, expected command outcomes, and tag correctness remain human review. Intentional Markdown demonstration code is not treated as real article headings/images.
- All elevated candidates were checked against current source structure: all four multiple-H1 articles, all 30 non-KB empty-header intended Markdown tables (including two caption-adjacent cases) plus the two nested HTML tables, and every repeated-unlabelled-fence article. Misnested fence cases were additionally read with surrounding source and list indentation; their spurious closing-fence blocks are not double-counted as ordinary missing language labels. This limited source judgment is not line-by-line expert review of every article or every semantic dimension.
